# Upstream documentation snapshot — USDA ESMIS

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the pages and the
document in the table below and refreshed deliberately by PR, so that changes show up as
diffs. This file is generated by the same script. Nothing here was edited by hand.

## Attribution

The documentation and the release files are works of the United States Government (USDA,
National Agricultural Library, ESMIS, https://esmis.nal.usda.gov), in the public domain
in the United States under 17 U.S.C. § 105. The visible text of the pages this script
reads prints no copyright line, licence or terms of use, and the OpenAPI document's
`info` names no licence, terms of service or contact. The site's footer lists 13 links
under "Government Links"; two of them could carry terms of use and are the ones read.
USDA states its policy at https://www.usda.gov/policies-and-links, which the CDN edge
answers with 403 Access Denied to this script, so what it states is not read here; the
Information Quality page, https://www.ars.usda.gov/docs/quality-of-information/, states
no copyright, licence or terms of use. The script stops if any page it reads starts to
state one. The documentation's text is reproduced here as this package's reference
(ADR-0003); an objection from the publisher is met by replacing it with a summary that
keeps the names and semantics the wrappers rely on.

## How this is captured

ESMIS documents its API on https://esmis.nal.usda.gov/api-documentation, a Drupal page
whose main content is an empty Swagger UI container. The Swagger UI renders the OpenAPI
document that the page's `drupal-settings-json` names at
`swaggerUIFormatter.swagger_file-0.swaggerFile`, as of this run
https://esmis.nal.usda.gov/sites/default/files/swagger/esmis_public_api.yaml. The script
reads the URL from there, stops if the key is gone or the URL leaves
https://esmis.nal.usda.gov, and saves the document verbatim, byte for byte, as
`openapi/esmis_public_api.yaml`, with the line endings it is served with;
`.gitattributes` keeps `docs/upstream/**` as `-text`, so git does not convert them. The
documentation page itself gets a row without a file.

The publication page of the World Agricultural Supply and Demand Estimates (WASDE) and
the view page of its newest release, the first row of the publication's release list,
are converted to Markdown with the standard library's `html.parser`. The page's main
content is kept; its breadcrumbs, the site's header, navigation and footer and the
screen-reader-only text inside links are dropped. Links become absolute URLs and a date
its text with its `datetime` attribute in parentheses; the release list's date filter
and its paging controls become one line each, the months offered and the last page. No
table on these pages has merged cells or a nested table, so none is kept as HTML. The
run stops on a page structure the converter does not know, and when the release list's
first row is not the page's Latest Release. Both files change with every release; their
rows' Bytes and sha256 are those of the HTML pages.

The release calendar has no HTML table: the browser draws it from the events in the
page's `drupal-settings-json`. `pages/release-calendar.md` is an excerpt: the page's
heading, the calendar's settings without the events, the events' count and field names,
and the first 10 events, one JSON object per line, all re-serialised with `json.dumps`,
values as fetched (upstream writes `/` as `\/`); then a line counting the events not
kept. Its row's Bytes and sha256 are those of the full page, and its Last-Modified is
the time Drupal last rendered it.

Pages without documentation text get no file, only a row: the API documentation page,
with its HTTP status and the size and sha256 of its body; ESMIS's former API address at
Cornell's Mann Library, https://usda.library.cornell.edu/api, which redirects to
https://esmis.nal.usda.gov/api, which answers 404, recorded by status only; and the two
footer pages under Attribution, USDA's by status only, since its 403 body carries a
per-request reference.

Against the same upstream, two runs write byte-identical files under `openapi/` and
`pages/`, and this file differs in its Fetched column and in the ETag and Last-Modified
of any ESMIS page that Drupal rendered anew in between. Drupal renders these pages into
a cache, and their ETag and Last-Modified are the time of that rendering, so a new
rendering changes them even when the page is the same byte for byte. Ids that Drupal may
generate per rendering (`js-view-dom-id-…`, form ids) are left out of the Markdown
files; where a new rendering changes them, the page's Bytes and sha256 change here too.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row; Last-Modified is the HTTP header in UTC, ETag as sent. Requests go one at a
time, 2 s apart, each retried at most once, identified as `xippios-usda-esmis
refresh_upstream (+https://github.com/xippios)`; no API key is sent or read.
