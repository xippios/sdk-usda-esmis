# Upstream documentation snapshot — USDA ESMIS

Source of truth for every endpoint wrapper (sdk-core ADR-0028). The files in this
directory are written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the
pages in the table below and refreshed deliberately by PR, so that changes show up as
diffs. This file is generated by the same script; nothing here is edited by hand but
`OBSERVED.md`, where it exists: what upstream does but never documents, each note with
its evidence.

## Attribution

None stated: no page this script reads states a copyright line, a licence or terms of
use.

The script stops when a page it reads states one it does not record, or no longer prints
one it records. The documentation's text is reproduced here as this package's reference
(sdk-core ADR-0028); the publisher's objection is met by replacing it with a summary
that keeps the names and semantics the wrappers rely on.

## How this is captured

ESMIS documents its API on https://esmis.nal.usda.gov/api-documentation, a Drupal page
whose main content is an empty Swagger UI container. The Swagger UI renders the OpenAPI
document that the page's `drupal-settings-json` names at
`swaggerUIFormatter.swagger_file-0.swaggerFile`. The script reads the URL from there,
stops if the key is gone or the URL leaves https://esmis.nal.usda.gov, and saves the
document verbatim, byte for byte, as `openapi/esmis_public_api.yaml`, with the line
endings it is served with; `.gitattributes` keeps `docs/upstream/**` as `-text`, so git
does not convert them. The document is YAML, so the script reads its `info` itself: it
names no licence, terms of service or contact. The documentation page itself gets a row
without a file.

The publication page of the World Agricultural Supply and Demand Estimates (WASDE) and
the view page of its newest release, the first row of the publication's release list,
are converted to Markdown with the standard library's `html.parser`. The page's main
content is kept; its breadcrumbs, the site's header, navigation and footer and the
screen-reader-only text inside links are dropped. Links become absolute URLs and a date
its text with its `datetime` attribute in parentheses; the release list's date filter
and its paging controls become one line each, the months offered and the last page. No
table on these pages has merged cells or a nested table, so none is kept as HTML. The
run stops on a page structure the converter does not know, and when the release list's
first row is not the page's Latest Release. Both files change with every release.

The release calendar has no HTML table: the browser draws it from the events in the
page's `drupal-settings-json`. `pages/release-calendar.md` is an excerpt: the page's
heading, the calendar's settings without the events, the events' count and field names,
and the first 10 events, one JSON object per line, all re-serialised with `json.dumps`,
values as fetched (upstream writes `/` as `\/`); then a line counting the events not
kept. Its row's Last-Modified is the time Drupal last rendered it.

Pages without documentation text get no file, only a row: the API documentation page and
the footer's Information Quality page. ESMIS's former API address at Cornell's Mann
Library, https://usda.library.cornell.edu/api, redirects to
https://esmis.nal.usda.gov/api on another host, which is not followed, and USDA's policy
page answers 403 at the CDN edge: both stand under Not fetched.

Against the same upstream, two runs write byte-identical files under `openapi/` and
`pages/`, and this file differs in its Fetched column and in the ETag and Last-Modified
of any ESMIS page that Drupal rendered anew in between. Drupal renders these pages into
a cache, and their ETag and Last-Modified are the time of that rendering, so a new
rendering changes them even when the page is the same byte for byte. Ids that Drupal may
generate per rendering (`js-view-dom-id-…`, form ids) are left out of the Markdown
files; where a new rendering changes them, the page's Bytes and sha256 change here too.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's, an excerpt's the whole document's, a file split from a page the
page's. Last-Modified is the HTTP header in UTC, or as sent in a code span where it is
no HTTP date, and ETag is as sent, in a code span, on a row that ends in a comment
telling the secret scan it is no key. A page recorded without a file is `(no file)`, and
a body that changes on every request records no size, sha256 or ETag. A sample is a
small answer of the API kept verbatim under `samples/`, which documents the answer's
shape and is no test fixture. Requests go one at a time, 2 s apart, through core's
client, each retried at most once and no sooner than 10 s, a 429 after the wait the
client gives it where that is longer, and are identified as
`xippios-usda-esmis/<version> (+https://github.com/xippios)`, the source package's
version in place of `<version>`. No redirect to another host is followed and no browser
is imitated. No key is sent or read. A page an anonymous client cannot read is requested
once and listed under Not fetched.

## Public domain

The documentation and the release files are works of the United States Government (USDA,
National Agricultural Library, ESMIS, https://esmis.nal.usda.gov), in the public domain
in the United States under 17 U.S.C. § 105. The site's footer lists 13 links under
"Government Links"; two of them could carry terms of use and are the ones read. USDA
states its policy at https://www.usda.gov/policies-and-links, which the CDN edge answers
with 403 Access Denied to this script, so what it states is not read here (Not fetched);
the Information Quality page, https://www.ars.usda.gov/docs/quality-of-information/,
states no copyright, licence or terms of use.
